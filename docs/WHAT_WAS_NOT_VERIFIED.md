# What Was Not Verified and Known Limitations

In accordance with Section 1 (Non-Negotiable Honesty Rules) and the UI Addendum of the project specifications, this document details every unverified assumption, synthetic test, hardware proxy, and operational limitation of the Edge Health Monitor project.

---

## 1. Physical Hardware and Microcontroller Execution
- **Physical Microcontroller Testing:** No physical ARM Cortex-M silicon, STMicroelectronics Nucleo board, or hardware target was flashed or measured. All Cortex-M4 latency figures in the report and dashboard are **analytic estimates** based on layer multiply-accumulate operations (MACs), an assumed clock frequency of 64 MHz, and CMSIS-NN cycle-per-MAC approximations (1.25 cycles/MAC for INT8, 4.0 cycles/MAC for FP32).
- **Desktop CPU Latency vs Embedded Latency:** Desktop inference latencies were measured using the TensorFlow Lite C++ runtime / Python Interpreter on an x86_64 host CPU over 200 iterations. These figures are relative benchmarks and do not reflect embedded memory bus constraints, cache misses, or low-power clock scaling.
- **SRAM (Tensor Arena) Footprint:** Peak RAM consumption was estimated by parsing the execution plan and persistent intermediate tensor buffer sizes via `interpreter.get_tensor_details()`. Actual SRAM consumption on hardware will vary based on compiler alignment, heap overhead, and the TFLite Micro tensor allocator arena layout.
- **CMSIS-NN Acceleration:** CMSIS-NN kernel optimizations were analyzed analytically and compared against unoptimized reference kernels in the report survey. No on-chip benchmark was executed using CMSIS-NN.

---

## 2. Dataset Scope and Behavioral Limitations
- **UCI HAR Fall Data Absence:** The UCI Human Activity Recognition dataset contains six activity classes (WALKING, WALKING_UPSTAIRS, WALKING_DOWNSTAIRS, SITTING, STANDING, LAYING) and **contains no fall instances**. Consequently, the 1D-CNN does not directly classify falls. The system employs a rule-assisted heuristic (acceleration magnitude spike $> 2.5\text{ g}$ followed by low-variance stillness), while the CNN provides posture confirmation (`LAYING` confidence $> 0.70$).
- **Synthetic Fall Verification:** All fall detection tests in the test suite and simulated replay pipeline were conducted using synthetic impact-spike-then-stillness acceleration trajectories. No human subject fall data was collected or verified on hardware.
- **Speech Commands Emergency Keyword:** The Google Speech Commands v0.02 dataset does not contain the word "help". The emergency keyword was configured as **"stop"** (the closest safety-related command in the 35-word vocabulary).
- **Background Noise Slices:** The `silence` class was generated by slicing 1-second segments from the `_background_noise_` directory with random amplitude scaling.

---

## 3. Real Android Phone Testing
- **Physical Handheld Deployment:** The web-based mobile sensor interface (`/phone`) uses the standard W3C DeviceMotionEvent API and Web Audio API. End-to-end integration was verified using an automated synthetic WebSocket client (`tests/test_live_pipeline.py`) and simulated replay streams (`src/demo_replay.py`).
- **Sensor Placement and Accuracy:** Real-world classification accuracy on a physical phone will be lower than the held-out test set accuracy due to pocket orientation shifts, non-standard sensor axes, accelerometer calibration drift, and mobile browser sample rate jitter.
- **Wi-Fi Network Restrictions:** On campus or enterprise networks with client-to-client isolation (AP isolation), direct LAN connections between phone and laptop may be blocked. The documented fallbacks (USB reverse port forwarding via `adb reverse` and mobile hotspot mode) provide reliable connectivity.

---

## 4. Federated Learning Simulation
- **Single-Machine Virtualization:** Federated learning (FedAvg) was executed as a single-machine simulation in TensorFlow. Network latency, packet dropouts, client dropouts, and asynchronous stragglers were not simulated.
- **Communication Cost:** Transfer sizes (KB/round) were computed analytically from model parameter count and data types (FP32 vs INT8 quantized deltas).

---

## 5. Adversarial Security Scope
- **Feature-Space White-Box Attack:** Adversarial robustness was evaluated using the Fast Gradient Sign Method (FGSM) directly on precomputed 40-band MFCC representations. This serves as a mathematical proxy for adversarial perturbations; physical acoustic over-the-air attacks against the microphone transducer were not evaluated.
